# Property detail — `/properties/{slug}`

> Draft to be refined together. Describes the desired UI and behaviour of a single property page.

## Purpose
Public page showing one approved listing in full — photos, facts, description, location and the
listing agent — so a Visitor can decide whether to inquire. Rendered in the public shell (`x-public-layout`).

## Access rules
- Public (no authentication).
- Only **approved** (`is_active = true`) and **not sold** listings resolve; anything else is a **404**.

## Content
- Back link → `/properties`.
- **Gallery**: large featured image (or first) + a grid of the remaining photos; placeholder when none.
- **Header**: name, address, badges for type/area/status + labels.
- **Facts**: bedrooms, bathrooms, half baths (if > 0), parking (if > 0), lot m², construction m².
- **Description**.
- **Features** (amenity categories).
- **Sidebar**:
  - Price in USD; additionally MXN when the property's `show_both_prices` flag is on.
  - Location block + a **"View on map"** external Google Maps link (by coordinates when set, else by address).
  - **Listing agent** card: photo/initials, name, bio, `tel:` phone, `mailto:` email.

## Notes
